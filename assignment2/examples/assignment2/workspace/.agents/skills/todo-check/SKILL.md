# Check a task-list change

For a coding plan, read the current requirement and source files first.
Read `checklist.md` beside this Skill when choosing verification cases.
When asked only to explain this Skill, read these two files and answer directly;
no application change or earlier run is needed. If a required input is absent,
state what is missing instead of guessing file names or searching runtime logs.
During planning, list checks without running commands or changing files.
After user approval, inspect actual function results and CLI output before
reporting completion. Historical results do not verify changed requirements.
